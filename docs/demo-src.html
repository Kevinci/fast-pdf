pdf.watermark("DRAFT", { color: ACCENT, opacity: 0.05 });   // on every page

// Image, clipped to a circle — real vector clipping, no Canvas needed

fast-pdf has six import paths. Which one you pick decides what ends up in your bundle — and what you can rely on across upgrades:

Import What it is Stability
fast-pdf PDFDocument and everything needed to build a document. This is the package. SemVer
fast-pdf/dom tableToPDF() and friends — reads a <table> off the page. Browser only. SemVer
fast-pdf/pdfa pdfA() — PDF/A-3b/-3u output and embedded files. Opt-in. More SemVer from 1.1.0
fast-pdf/zugferd facturX() — ZUGFeRD / Factur-X invoices (PDF/A-3 + embedded XML). Opt-in. More SemVer from 1.1.0
fast-pdf/internal The engine below PDFDocument: PDFWriter, ContentStream, Name, serialize, … none — may break any release

Embedded fonts are set the way the font was designed to be set: pair kerning (from GPOS, or the legacy kern table) and the font’s standard ligatures — fi, fl, ffi (from GSUB) — are applied by default, for every text fast-pdf draws: text(), tables, Markdown, headers and footers, the table of contents, SVG text. Measuring uses the same glyph run as drawing, so widthOfText() and measureText() always agree with the page, and a ligature still copies and searches as the letters it replaced. Both can be switched off per font:

Eingebettete Schriften werden so gesetzt, wie die Schrift es vorsieht: Paar-Kerning (aus GPOS oder der älteren kern-Tabelle) und die Standard-Ligaturen der Schrift — fi, fl, ffi (aus GSUB) — sind standardmäßig aktiv, für jeden Text, den fast-pdf zeichnet: text(), Tabellen, Markdown, Kopf- und Fußzeilen, Inhaltsverzeichnis, SVG-Text. Gemessen wird mit demselben Glyphenlauf wie gezeichnet — widthOfText() und measureText() stimmen also immer mit der Seite überein, und eine Ligatur lässt sich weiterhin als die ersetzten Buchstaben kopieren und suchen. Beides ist pro Schrift abschaltbar:

嵌入字体按照字体本身的设计进行排版：字偶距调整（来自 GPOS 或旧式 kern 表）和字体的标准连字——fi、fl、ffi（来自 GSUB）——默认启用，适用于 fast-pdf 绘制的所有文本：text()、表格、Markdown、页眉页脚、目录、SVG 文本。测量与绘制使用同一组字形序列，因此 widthOfText() 和 measureText() 的结果始终与页面一致；连字在复制和搜索时仍还原为被替换的原始字母。两者都可以按字体关闭：

The built-in fonts (helvetica, times, courier) are not kerned: fast-pdf carries their widths, not their kerning tables. Kerning tightens pairs like “AV” and “To”, so text in an embedded font can run narrower than in 1.1 and line breaks can move; { kerning: false, ligatures: false } restores the old metrics.
Gut zu wissen: Gesperrter Text (letterSpacing) behält sein Kerning, bildet aber keine Ligaturen — eine Ligatur lässt sich nicht sperren. Die eingebauten Schriften (helvetica, times, courier) werden nicht gekernt: fast-pdf bringt ihre Breiten mit, nicht ihre Kerning-Tabellen. What comes from the CSS

Was aus dem CSS kommt

哪些内容来自 CSS

Cell backgrounds, text colors, per-side borders, font sizes, weights, italics, padding, alignment and the column proportions all come from getComputedStyle() — including modern color spaces like oklch() and color(display-p3 …). Rows hidden by CSS stay out, and a selector (skip: ".no-print") drops whatever else does not belong in the file. The surface counts too: a row without its own background is transparent in the browser and shows the card or page behind it, so the PDF page is painted in that colour. Without it, a table from a dark interface would arrive as light text on white paper. background takes a colour of your own, or false to keep the paper white.

Zellhintergründe, Textfarben, Rahmen pro Seite, Schriftgrößen, -schnitte, Kursivstellung, Padding, Ausrichtung und die Spaltenverhältnisse kommen alle aus getComputedStyle() — auch moderne Farbräume wie oklch() und color(display-p3 …). Per CSS versteckte Zeilen bleiben draußen, und ein Selektor (skip: ".no-print") wirft alles Weitere raus, was nicht in die Datei gehört. Auch der Untergrund zählt: Eine Zeile ohne eigenen Hintergrund ist im Browser durchsichtig und zeigt die Karte oder Seite dahinter — deshalb wird die PDF-Seite in genau dieser Farbe eingefärbt. Ohne das käme eine Tabelle aus einem dunklen Interface als heller Text auf weißem Papier an. background nimmt eine eigene Farbe, oder false für weißes Papier.

单元格背景、文字颜色、逐边框线、字号、字重、斜体、内边距、对齐方式以及列宽比例，全部来自 getComputedStyle()——包括 oklch() 和 color(display-p3 …) 这类现代色彩空间。被 CSS 隐藏的行不会进入文件，再用一个选择器（skip: ".no-print"）剔除其余不该出现的内容。背景同样重要：没有自身背景色的行在浏览器中是透明的， 显示的是其后的卡片或页面，因此 PDF 页面会被填充为该颜色。否则， 来自深色界面的表格就会变成白纸上的浅色文字。background 可指定自定义颜色，false 则保持白色纸张。

One thing genuinely cannot travel: web font files. CSS names a font, it never hands over its bytes, so a family the document does not carry is mapped onto the closest built-in one. Register the real file with registerFont() and pass it as table.font when the typeface has to match exactly.

Eines kann wirklich nicht mit: Webfont-Dateien. CSS nennt eine Schrift, liefert aber nie ihre Bytes — eine Familie, die das Dokument nicht mitbringt, wird auf die nächstliegende eingebaute abgebildet. Wenn die Schrift exakt stimmen muss, registriere die Datei mit registerFont() und übergib sie als table.font.

确实有一样东西带不走：Web 字体文件。CSS 只给出字体名称，从不交出字节，因此文档未携带的字族会被映射到最接近的内置字体。若字体必须完全一致，请用 registerFont() 注册真实文件，并作为 table.font 传入。

Not supported Notes
Editing existing PDFs Pages can be appended, not modified. Text in an imported page cannot be changed; encrypted sources are rejected.
PDF/A-1, PDF/A-2, PDF/A-3a PDF/A-3b and -3u are supported through fast-pdf/pdfa (planned for 1.1). Parts 1 and 2 are not (part 3 is what e-invoicing needs), and level A needs tagged PDF. PDF/A cannot be combined with encryption, append() or CMYK JPEGs.
Tagged PDF (StructTreeRoot) Not supported, no date set. /Lang and /DisplayDocTitle are written — that is all; no /MarkInfo, no structure tree, no reading order.
PDF/UA Not supported, no date set. No deadline in force names PDF/UA (the BFSG names neither EN 301 549 nor PDF/UA); to be re-assessed once EN 301 549 is harmonised.
XMP metadata outside PDF/A An ordinary document carries only the classic /Info dictionary. XMP is written in PDF/A mode, where it is mandatory.
Archivable output with the default font Standard-14 fonts are referenced without a FontFile, i.e. not embedded, and fast-pdf ships no font of its own. PDF/A therefore needs registerFont() with a TTF for all text — pdfA() refuses to render otherwise.
Creating or validating invoice XML fast-pdf/zugferd builds the hybrid container. The CII XML — EN 16931 business rules, VAT categories, code lists — comes from you; use an e-invoicing library to create and validate it.
List boxes, comb fields, form logic Text fields, checkboxes, radio groups and dropdowns are supported. Multi-select list boxes, comb fields, calculations/JavaScript and submit/reset actions are not.
Hyphenation patterns, font fallback hyphenate takes a function; no patterns are bundled. A character missing from the font is not looked up in another font — it is drawn as the font’s “missing glyph” box.
WOFF/WOFF2 fonts Needs Brotli. Convert to .ttf at build time.
Complex-script shaping, contextual features Pair kerning and standard ligatures are applied. There is no shaping engine: Arabic/Devanagari are not usable, not merely suboptimal, and contextual alternates, discretionary ligatures and mark positioning are not applied. The built-in fonts are not kerned.
Gradients (/Shading), patterns Flat fills and constant alpha only.
CFF-flavoured OpenType, .ttc Rejected with an actionable error.
Lossy WebP, interlaced PNG Rejected with UNSUPPORTED_IMAGE.
HTML pages → PDF tableToPDF() reads a <table>, not a whole page. No general HTML/CSS layout engine; web font files cannot be read from CSS.
Tree-shaking within one entry point Measured at 0.2 % — effectively nothing. Code is removed by picking the right entry point, not by the bundler.

PDF/A-1, PDF/A-2, PDF/A-3a PDF/A-3b und -3u werden unterstützt, über fast-pdf/pdfa (geplant für 1.1). Teil 1 und 2 nicht (Teil 3 ist, was die E-Rechnung braucht), und Stufe A braucht getaggtes PDF. PDF/A lässt sich nicht mit Verschlüsselung, append() oder CMYK-JPEGs kombinieren.

25Changelog

Release notes, newest first — kept in English so they match CHANGELOG.md in the repository one to one. The format follows Keep a Changelog, versioning follows SemVer.

1.2.02026-11-27Typography and forms: kerning, ligatures and a hyphenation hook for embedded fonts; fillable text fields, checkboxes, radio groups and dropdowns.

Additive API — nothing was removed or changed. Text in embedded fonts can set narrower than in 1.1 (see Changed).

Added

  • Kerning. Embedded fonts are kerned: pair adjustments from GPOS (feature kern, pair lookups format 1 and 2, also through an extension lookup) or from the legacy kern table. Applied to every text fast-pdf draws — text(), tables, Markdown, headers and footers, the table of contents, SVG text — and to every measurement, so widthOfText() and measureText() agree with the page.
  • Ligatures. The font’s standard ligatures (GSUB feature liga: fi, fl, ffi …) are formed. The ToUnicode map records every character a ligature replaced, so copy, search and PDF/A-3u keep working.
  • registerFont(data, { kerning, ligatures }) switches either off per font. Both default to true.
  • hyphenate document option — a function from a word to its syllables, used by text(), measureText() and table cells. No patterns are bundled: plug in a hyphenation library for your language.
  • Form fields. textField() (single-line, multiline, password, maxLength), checkbox(), radioGroup() and dropdown() (optionally editable) write fillable AcroForm fields, placed in the flow or absolutely like signature(). Every field carries real appearance streams — no /NeedAppearances — so pre-filled values print. Names are required and unique across all fields, signatures included.

Changed

  • Text set in an embedded font can be narrower than in 1.1, because kerning tightens pairs like “AV” and “To”; line and page breaks can move. Layout changes like this are outside the SemVer promise; pass { kerning: false, ligatures: false } to registerFont() for the old metrics. Documents using only the built-in fonts are unaffected.
  • Letter-spaced text keeps kerning but forms no ligatures.
  • A password field’s value is never written into the file. PDF/A mode rejects the new form fields with PDFA_VIOLATION (their text is set in the non-embedded Helvetica); signature fields stay allowed.
  • The core grows to ~54 KB min+gzip (fast-pdf 54,040 B): form fields live on PDFDocument, and the OpenType layout-table reading is part of the font code every entry point shares.
1.1.02026-11-27Purely additive: two new entry points for PDF/A-3 and ZUGFeRD/Factur-X, one new error code, no change to anything 1.0.0 froze.

Planned as 1.1.0, not on npm yet. Purely additive: two new entry points, one new error code, no change to anything 1.0.0 froze.

Added

  • PDF/A-3 output — fast-pdf/pdfa. pdfA(doc) turns a document into PDF/A-3b (or -3u with { conformance: "U" }): an XMP metadata stream mirrored from the document’s metadata and an sRGB output intent. At render time it refuses, with a message that says what to change, the non-embedded built-in fonts, a character the font has no glyph for, encrypt, append() and CMYK JPEGs. Signature fields and PAdES signing keep working.
  • Embedded files. pdfA(doc).attach({ … }) embeds a file as an associated file of the document. This is the only way fast-pdf writes an embedded file, and it is not reachable from the main entry.
  • ZUGFeRD / Factur-X — fast-pdf/zugferd. facturX(doc, xml, { profile }) builds the hybrid e-invoice container: PDF/A-3, the XML embedded as factur-x.xml (xrechnung.xml for XRECHNUNG), /AFRelationship from the specification’s profile matrix, and the four fx: XMP properties. All six profiles. The XML is yours: fast-pdf checks that it is a CII invoice whose guideline ID matches the profile, and does not create or validate invoice data.
  • The sRGB profile is bundled — 456 bytes, CC0 — as data in the code, so PDF/A works in browsers, on edge runtimes and under every bundler.
